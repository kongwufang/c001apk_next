# 消息中心：账号隔离与动态快照（2026-11-21）

## 用户期望

“所有消息”保留同账号的快速缓存显示，但缓存必须跟随后续成功加载的最新结果：已消失的消息删除，中间新增的消息按时间补入，同一消息正文等内容变化及时刷新。切换账号不能先闪出上个账号的消息。

## 实现

- 缓存按 UID 的 SHA-256 分文件；未登录不恢复缓存。旧版没有账号标识的全局缓存无法安全确定归属，首次读取时删除，不猜测迁移。
- 账号身份附带持久化代际号；登录状态或 UID 真正变化时，与身份字段同一 SharedPreferences 事务更新。旧请求持有原始身份与请求代际，返回时复核，不能用返回时的当前账号给旧结果重新贴标签。令牌正常续期不会使同账号缓存失效。
- Activity 在身份变化时同步清空旧列表，再合并身份通知重新绑定，防止异步 Diff 保留旧账号行；从后台返回也重新核对。
- 刷新并行读取五个分类，每个分类从第一页重建已展示窗口，成功的分类整体替换旧快照；失败的分类保留原快照，不能将失败当成“服务器确实返回空列表”。成功空结果会持久化空快照。
- 以“分类 + 消息 ID”去重，按 dateline 降序统一排序；不只追加，因此可以删除、移动、在中间插入。DiffUtil 的内容比较使用完整数据结构，支持同 ID 的正文、头像、跳转对象等变化。
- 翻页展开目标 N 条之前，每个未结束分类至少读取 N 条；避免某个分类的旧缓存先显示、另一个分类较新的第二页后插入。网络已读完但仍有缓冲行时，继续允许展开。
- V18 原始页条数及尾游标随归一化保留，避免过滤后的空页被当成流结束；赞列表缺少 id 时使用原始 entityId 游标。
- 删除/屏蔽成功时取消旧列表请求，避免先前请求重新带回已经移除的项目。屏蔽按发送者过滤整个快照。
- 缓存写入在 IO 串行执行，保留提交顺序；已读账本也按账号分隔。

## 自动化回归范围

- 成功刷新删除旧消息、中间插入、同 ID 内容更新和落盘。
- 真空结果清空旧缓存；单分类失败保留该分类，其余成功分类正常更新。
- 同 ID 不同分类独立；完整内容差异驱动重绑定。
- 账号 A/B 缓存隔离，A→B→A 及退出后回到 A 的旧请求不能写入。
- 无归属旧缓存丢弃、损坏缓存安全回退、令牌续期不误判切号。
- V18 过滤空页继续翻页；全部网络源结束后仍可展开缓冲行。
- 两类时间跨度明显不同时，第二页优先展示真正较新的消息。
- 切号取消挂起的旧请求后，新账号 UI 与缓存保持不变。
