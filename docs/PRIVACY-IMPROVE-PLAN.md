# 「加入用户体验改善计划」隐私说明

> 这份文档对应 App 首次启动欢迎流程第 4 步里那个开关，以及
> 「设置 → 高级 → 加入用户改善计划」。
>
> 目的：**让你清楚知道打开/关闭这个开关，分别会发生什么**。你可以随时在设置里改。

## 一句话总结

| 开关状态 | 会发生什么 |
|---|---|
**打开** | 服务器会下发「诊断请求」，客户端在被请求时上传一份**技术性诊断包**，用来定位你反馈的问题（崩溃、闪烁、加载失败等） |
**关闭**（默认） | 客户端仍会发心跳（只报告"我在线"），但**不会上传任何诊断包、也不会执行服务器下发的事件** |

## 打开之后，服务器能看到什么

诊断包是这样一个 JSON（字段不随本说明变化，新增字段会更新本文档）：

```json
{
  "schema": 1,
  "time": "2026-11-08T14:13:15",
  "app":    { "ver": "<本 App 版本>", "code": "<versionCode>", "api": 1,
              "debug": false, "pkg": "com.example.c001apk", "sig": "<签名哈希前12位>",
              "firstInstall": 0, "lastUpdate": 0 },
  "device": { "brand": "OPPO", "model": "R11 Plus", "build": "...", "android": "9",
              "sdk": 28, "abi": ["arm64-v8a"], "isTablet": false, "isNight": true,
              "density": 240, "fontScale": 1.0, "screen": "1080x1920",
              "locale": "zh-CN", "timezone": "Asia/Shanghai" },
  "state":  { "登录态": false, "主题": "...", "若干开关状态": "..." },
  "errors": [ "最近 5 条崩溃摘要（每条前 5 层调用栈）" ],
  "http":   { "enabled": false, "聚合统计": "仅在你自己打开「记录 HTTP 请求日志」后才有" },
  "applog": { "dropped": 0, "lines": ["最近 200 行 App 日志"], "memory": ["内存缓冲里最近 100 条"] }
}
```

### 具体说明

1. **设备与系统**：品牌、型号、系统版本、SDK、ABI、屏幕尺寸/密度、字体缩放、夜间模式、语言、时区。
   —— 用于复现「只有某个机型/系统出问题」的 bug。

2. **App 与安装**：本 App 的版本名/版本号、是否 debug 构建、包名、**签名哈希前 12 位**、首次安装时间、最近更新时间。
   —— 用于判断是否旧版本、是否被二次打包。

3. **崩溃摘要**：最近 5 条未捕获异常的**类型、消息、前 5 层调用栈**（不含你输入的任何内容）。
   —— 用于定位闪退。

4. **App 日志（最近 200 行）**：模块化的运行日志，例如
   `I/net/SslVerify 内置 Mozilla CA 库加载完成`、`I/card/HomeFeedViewModel PAGE_LOAD …`。
   —— 用于定位"加载失败/卡片不显示/点了没反应"。

5. **HTTP 日志聚合**：**只有你自己在「日志」页打开「记录 HTTP 请求日志」时才会有**；
   内容为请求方法、URL、状态码、耗时，以及截断到 2KB 的请求/响应体。

## 明确**不会**上传的内容

- 你的账号密码、Cookie、`token`、`ssaid`、`uid`、用户名等登录凭据
  （日志与诊断包里的这些字段在**落盘和上传前**就被替换成 `***`）
- 你的照片、文件、剪贴板内容
- 你在 App 里输入的搜索词/回帖正文
- 通讯录、短信、位置（除非你自己在系统里授权了定位且使用了相关功能）

## 上报是怎么发生的

1. App 每 N 分钟发一次心跳 `GET /c001apk/heartbeat`（只带设备与版本信息）；
2. 心跳响应里若带 `{"events":[{"op":"log", ...}]}`，客户端才会上传诊断包；
3. 上传地址：`POST /c001apk/diag/`，**gzip 压缩**，服务端按 `ssaid` 前 2 位分片存放；
4. 服务端保留 7 天后自动删除。

## 怎么关闭 / 怎么删除已上传的数据

- 关闭：`设置 → 高级 → 加入用户改善计划`（关掉后不再上传诊断包，也不再执行服务端下发的事件）
- 同时建议关掉：`日志 → 记录日志`（那是本机的日志落盘开关，关掉后连本机也不记录）
- 删除已上传：把设备的 `ssaid` 或你的 GitHub issue 编号发给作者，即可定位并删除对应快照

## 附：服务器下发的「事件」能做什么

开关打开时，服务器可以下发这几类事件（都有客户端白名单，超出即忽略）：

| op | 作用 |
|---|---|
`toast` / `dialog` | 弹提示 |
`notice` | 推一张公告卡到「我的」 |
`update` | 提示更新（不静默安装） |
`gates` | 刷新云端开关（如临时关闭某个入口） |
`clearCache` / `reload` | 建议客户端清缓存/重载当前页 |
`open` | 打开白名单内的链接（houlangs.cn / coolapk.com / github.com） |
`log` | 请求一次上面说的诊断包 |

这些事件**不会**：读取你的文件、静默安装应用、后台截图、上传通讯录。
