## 一、搜索「综合」tab（混合卡片流）

### 是什么

官方搜索结果第一页是「综合」，里面不是动态，而是**卡片混合流**：顶部横幅、话题卡、用户横滑卡、赞助位。
我们原来没有这一页，第一个 tab 直接是「动态」（纯动态）。

### 接口与数据结构（官方抓包实测）

```
GET /v6/search?type=all&searchValue=<关键词>&page=1&showAnonymous=-1&category=
⇒ data[] 里是各种 entityTemplate：
   imageScaleCard      顶部大图横幅
   listCard            url=tab://feedTopic  话题卡（内部 entityList 是话题项）
   iconScrollCard      url=tab://user       用户横滑卡（关键词「晚上刷机」会命中）
   sponsorForSearch    搜索赞助位
```

关键词对照（实测）：

| 关键词 | 返回模板 |
|---|---|
| 酷回收 | `imageScaleCard` + `listCard(话题)` + `sponsorForSearch` |
| 晚上刷机 | `iconScrollCard(用户)` + `sponsorForSearch` |

### 实现

```
ui/search/SearchResultFragment.kt
  · tabList 前面插入「综合」，getFragment 分支整体后移：
    0=综合(type=all) 1=动态(type=feed) 2=应用 3=游戏 4=数码 5=用户 6=话题
ui/search/SearchContentViewModel.kt
  · 修掉一个真 bug：原来 `if (isRefreshing || isLoadMore) { …add… }`，
    首次进 tab 两者都是 false ⇒ 一条都不入列 ⇒ 页面空白 ✗
    改成 `run { … }` 永远入列，清空仍由 isRefreshing 控制
```

### 验证（模拟器 dump）

```
搜索「小米14」→ 综合 tab：
  酷安首款定制手机壳 | 话题 | 更多 ›
  更多相关话题
  数码 | 更多 | 小米14 | 8.6分
```

## 二、搜索「动态」tab 的排序控件（官方 5 选一）

### 参数（官方 HAR + 线上重放逐步验证）

| 官方按钮 | 参数 | 说明 |
|---|---|---|
综合 | `sort=default` | 与不带 sort 结果完全一致 |
实时 | `sort=dateline` | 按发布时间 |
热度 | `sort=hot` | 与 reply 顺序不同，已验证 |
评论 | `sort=reply` | 按评论数 |
精确 | `sort=none` **且** `isStrict=1` | 官方是 `/v6/page/dataList?url=/SearchModel/feedSearchList?…&sort=none&isStrict=1` |

其余候选值（`realtime`/`exact`/`new`/`time`/`accurate`/`precise` …）实测一律返回 0 条，可判定为无效值。

### 实现

```kotlin
// adapter/ProductSortHeaderAdapter.kt
class ProductSortHeaderAdapter(
    currentSort: String,
    labels: List<Pair<String, String>> = DEFAULT_LABELS,   // 新增：可配置项
    onSort: (String) -> Unit
)
// 默认三段保持原样，话题页 / 产品讨论页行为不变
private val DEFAULT_LABELS = listOf("默认" to "默认", "最新" to "最新", "热度" to "热度")
val SEARCH_LABELS = listOf("综合" to "default", "实时" to "dateline",
                           "热度" to "hot", "评论" to "reply", "精确" to "none")

// ui/search/SearchContentFragment.kt
override fun topAdapter(): RecyclerView.Adapter<*>? =
    if (viewModel.type != "feed") null
    else ProductSortHeaderAdapter(viewModel.sort, SEARCH_LABELS) { value ->
        viewModel.isStrict = if (value == "none") 1 else 0
        onSearch("sort", value, null)      // 必须走这条，直接改 LiveData 不会重新请求
    }
```

配套改动：

```
ApiService.getSearch  加 @Query("isStrict") isStrict: Int = 0
Network / Repository  透传 isStrict（带默认值，旧调用不受影响）
NetworkRepo.getSearch 同步加参数（SearchContentViewModel 调用的是它）
search_menu.xml       增加「精确」；SearchResultFragment 增加映射与点击
```

### 验证（模拟器 dump）

```
动态 tab：综合 | 实时 | 热度 | 评论 | 精确   ← 5 个 chip 全部渲染
点「实时」「精确」：列表正常刷新，不空白、不崩溃
```

### 踩过的坑

```
· with(binding) 作用域里没有 itemView ⇒ 用 holder.itemView.context
· 点 chip 只改 LiveData ⇒ 列表被清空后不再请求 ⇒ 必须调 onSearch()
· 菜单与 chip 双向同步：菜单换排序后调 sortHeader?.notifyDataSetChanged()
```

## 三、实况图片（Live Photo）

### 识别规则（逆向自官方 dex，非猜测）

```
官方正则常量（classes07.dex 原文）：
  https?://\S+livepic\S*@\d+x\d+\.(jpg|jpeg|png|gif|webp)
⇒ URL 里带 "livepic" 即判为实况图，没有独立的 isLive 字段
（dex 里另有 isLive / isLivePicUrl / livePicUrl / livePhotoEnable / livePhotoScale /
  liveSoundEnable / livePhotoControlViewModel 等成员，以及 live_photo_tag /
  live_photo_view / live_photo_switch_view 三个 UI 资源名）
```

样本（`/feed/74957360`）：

```
cover = http://image.coolapk.com/feed/2026/1109/20/44881806_cbfafce2_7304_3823_91-livepic@872x1920.jpg
```

### 已实现

```
util/LivePhoto.kt
  isLive(url)                 URL 含 livepic
  coverUrl(url)               去掉 .s.jpg / .thumbnail.jpg 缩略后缀
  videoUrl(coverUrl)          去掉 @WxH.jpg 后补 .mp4（推测规则，见「已知限制」）
  extractMotionVideo(jpeg)    在 JPEG 字节流里找 ftyp 盒子，截取尾部拼接的 MP4

util/LivePhotoPlayer.kt
  全屏黑底 Dialog + 系统 VideoView，循环 + 静音（官方 liveSoundEnable 默认关）
  按钮：静图 / 保存 / 关闭
    静图  → 显示封面 + 暂停视频，按钮变「视频」，再点切回播放
    保存  → OkHttp 下载封面 jpg + 视频 mp4 到 App 专属外部目录
            /sdcard/Android/data/com.example.c001apk/files/Download/
            文件名用 URL 里的 hash 前缀（与官方一致）
  失败处理：视频地址不可用 ⇒ 先尝试 Motion Photo 解析（下载封面找尾部 MP4）
            仍失败 ⇒ 提示「该实况暂不支持播放，可先保存封面」（不假装能播）

adapter/ViewBindingAdapters.kt + res/layout/item_feed_content.xml
  setLiveBadge(picArr)：九宫格里任一图命中 livepic ⇒ 右上角显示「实况」角标

view/ninegridimageview/NineGridImageView.kt
  点击分流：实况 ⇒ LivePhotoPlayer.show()，其它 ⇒ 原 ImageUtil.startBigImgView（行为不变）
```

## 四、全局「长按选中文本」

### 行为

任意界面的文字，长按即可调出系统选择框（复制 / 全选 / 分享），不用进菜单。

### 实现

```kotlin
// ui/base/BaseActivity.kt
override fun onResume() {
    super.onResume()
    window?.decorView?.post { enableTextSelection() }
    // Fragment 列表是异步加载的，onResume 时视图不全 ⇒ 再补一次延迟扫描
    window?.decorView?.postDelayed({ enableTextSelection() }, 1200)
}

// 遍历窗口 View 树，给「不可点击」的 TextView 打开 textIsSelectable
// · EditText 本身可选，跳过
// · 可点击的 TextView（行/卡片）不动，避免抢掉原来的长按行为
// · 用 tag 标记已处理，避免每次 onResume 重复遍历
```

### 验证（模拟器）

```
长按评论「这个天气壁纸确实好看」⇒ 出现「复制 / 全选」系统选择框 ✓
```

### 踩过的坑

```
· View.tag 在 Kotlin 里只有 getter ⇒ 必须 setTag()/getTag()
· TextView.isTextSelectable 也是只读属性 ⇒ 必须 setTextIsSelectable(true)
· 只扫一次 onResume 不够（列表异步加载）⇒ 补 1.2s 延迟扫描
· 方案取舍：现在只对「不可点击」的文本生效（方案 A）；
  正文/评论常包在可点击行里 ⇒ 这类文字仍选不中，若要全支持需把点击下放到父容器
```

## 五、公告体系统一（心跳下发 + 公告池）

### 结构

```
data/heartbeat_notice.json  ┐
                            ├─→ /c001apk/notice/ → 客户端 NoticeRepo.fetch()
data/notice.json（原公告池）┘        （服务端合并去重后一次下发）
心跳响应仍可带 notices[]（应急推送，同 id 会被公告池去重）
```

### 服务端（`notice/index.php`，备份 `index.php.bak-merge`）

```
在 echo $__resp 之前把 heartbeat_notice.json 的 notices 并入 $__resp['cards']
  · 同 id 以公告池为准
  · until 日期过期跳过
  · 按钮只保留 http(s)，同时输出 text / name 两个键（兼容新老客户端）
  · 出错写 data/notice_merge_err.log，不影响主流程
```

### 客户端

```
NoticeRepo.parse()      服务端撤回的卡立刻从本机消失（pruneWithdrawn，按公告池 id 对齐）
StatsBeacon.ingestNotices  解析心跳响应里的 notices（字段白名单 + 按钮 http(s) 校验）
LivePhoto / 公告         字段白名单，不执行任何代码、不涉及权限、无需用户同意
```

### 验证

```
curl /notice/ 返回：致谢卡 + hb-notice-live-20261113（带「去更新页」按钮）
清空 heartbeat_notice.json 后：curl 只剩致谢卡 ✓
```

## 九、复制功能范围调整（`d6d966e9`）

### 用户问题

之前在 `BaseActivity` 中遍历整个窗口的 View 树，给大量 TextView 开启了系统文本选择。
这会让设置标题、搜索结果、卡片标签等不应该复制的文字也弹出「复制 / 全选」菜单，影响正常点击和长按交互。

### 新规则

```
普通页面：不启用全局文本选择
帖子详情正文：支持长按，调用系统选择框
帖子评论：支持长按，调用系统选择框
日志查看器、更新说明：保留各自已有的局部文本选择
```

### 实现位置

```
删除：ui/base/BaseActivity.kt 中的全局 enableTextSelection / walkForSelection 扫描及 onResume 延迟扫描
保留并明确开启：
  res/layout/item_feed_content.xml
  res/layout/item_feed_content_reply_item.xml
  res/layout/item_feed_reply.xml
```

这些布局中的正文/评论控件使用 `android:textIsSelectable="true"`，因此系统负责显示复制、全选和分享菜单。
选择能力限定在帖子内容控件，不再改写其他页面的 TextView 行为。
