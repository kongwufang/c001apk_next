# 数字联盟 ID 自动刷新（2026-11-15）

## 用户要求与行为

- 设置首页「推荐流相关」改名为「偏好设置」，保留原来的内部 screen key 和所有原有偏好，在其中增加「自动刷新数字联盟ID」。相关提示中的旧入口名称同步更新。
- 引导第 2 页（机型参数页）展示同一开关，首次展示为开启。修改暂存在页面状态中，点该页「下一步」才写入偏好；旋转和返回机型参数页保留草稿。
- 已完成旧引导的用户默认不自动启用，可在偏好设置中开启。引导完成前不自动取号。
- 开启时，在冷启动和从后台回到前台时检查：距离上次成功取号未满 24 小时不请求；满 24 小时则静默使用本地协议直连上游刷新。仅检查应用进入，不在应用内切换页面时反复检查。
- 成功后更新 ID、设备串首字段及获取时间；失败保留原 ID 和时间，下次进入应用仍可重试。手动取号成功或手动保存非空 ID 也重新开始计时；清空 ID 时清除时间。
- 旧版未保存获取时间，升级时为已有 ID 建立一次当前时间基准，保留它至少一个完整窗口；此后按实际成功时间推进。
- 无 ID 时，若已完成引导且打开开关，下一次进入应用会获取。系统时间倒退时不提前刷新，避免重复请求。

## 实现

- `PrefManager.autoRefreshSzlmId`：持久化开关，默认 false；`szlmIdLastObtainedAt`：成功获取时间，毫秒 Long。
- `DuidRefreshPolicy`：纯 JVM 24 小时边界规则。
- `SzlmIdAutoRefresh`：仅主进程安装 Activity 生命周期回调；前台状态通过 700ms 停止延迟避免旋转触发重复检查。一次只运行一个自动请求；显式取号页和引导页不启动自动请求。
- 关闭开关或进入手动取号时取消自动任务；返回结果前再次比对开关、当前 ID、时间，防止覆盖期间发生的手动更改。
- `SzlmIdPrompt.save` 共用成功保存路径，沿用原有设备串和有效性监测。
